** Status

M4, the first real server, is done: ~serve~ runs your handler on libuv,
answering each connection's requests one at a time, and curl and ApacheBench
get correct answers from it. Since M5 it also stops waiting for clients that
stall. Since M6 a handler reads a request's body as it arrives and can stream
its response, so a big upload or download is never held in memory whole.
Since M7 a handler can wait: for another request, a time, a deadline or a
name's lookup (see [[file:docs/handlers.org][docs/handlers.org]]). A connection
costs no more once its handler is done waiting, and one contract test holds all
three shells, waiting handlers included, to the same bytes. Since M8.1 it
shuts down gracefully: sent SIGTERM or SIGINT (Ctrl-C), it finishes the
requests in flight, closes the rest after ~CHEZ_HTTP_DRAIN_TIMEOUT~, and
~serve~ returns (see [[file:docs/connections.org][docs/connections.org]]). Since
M8.2 a handler can take an upgrade, a WebSocket's say, and speak the new
protocol over the connection itself (see [[file:docs/handlers.org][docs/handlers.org]]). M8.3 held
it to other servers' strict request tests, request-smuggling cases and vtest2's
scripts, and M8.4 to a load test with oha. v0.1.0 was the first release. Since
v0.2.0 a handler that waits is told when its client leaves, and a request in
HTTP/1.2 to 1.9 is served as 1.1. Since v0.3.0 code that speaks the new
protocol after an upgrade can wait as a handler does. Since v0.4.0 it can close
at once a client that stopped reading, and a handler can read every line of a
field. Since v0.4.1 a handler that waits holds about 0.7 KB until its wait
ends, about 3 KB less. Since v0.5.0 code that took an upgrade closes as the
server closes its own connections, so a client still sending reads its last
words, not a reset (see [[file:docs/handlers.org][docs/handlers.org]]). Since v0.6.0 that close gives up
on a client that reads nothing once the write timeout passes, and what a client
sends after the upgrade waits for code that starts reading late. Since v0.7.0,
the current release, that code may wait on a thunk that returns nothing, and
the test fake's door, which its own tests load, keeps unread bytes and bounds
a close as the server does. [[file:CHANGELOG.md][CHANGELOG.md]] has what
each release does, and the numbers measured for v0.1.0. See
[[file:.plans/2026-09-19-chez-http-server-project-brief.md][the project brief]] for the milestone map.

** Quick start

#+begin_src scheme
(import (rnrs) (http-server))

(serve
 (lambda (request)
   (make-response 200 #f '() (string->utf8 "Hello\n"))))
#+end_src

Save it as ~hello.sps~, start it with ~make run PROGRAM=hello.sps~, and
~curl http://127.0.0.1:8080/~. How a handler reads the request is in
[[file:docs/handlers.org][docs/handlers.org]].

** Build and test

Prerequisites:

- *Chez Scheme* 10.4.1 or later, threaded build (the binary is ~chez~)
- *libuv* 1.48 or later that ~pkg-config~ can see (~brew install libuv~, or
  ~apt install libuv1-dev~ on Ubuntu 24.04 or later), plus a C compiler — the
  chez-libuv shim is built from source. With no libuv, or an older one such as
  Debian 12's 1.44, chez-libuv builds its own, which needs CMake 3.10 or later
  (Debian 12's own builds it)
- For ~make test~, the real clients the tests run against the server: *curl*,
  *ab* (~apache2-utils~ on Linux), vtest2, which ~make vtest~ builds from
  source with *pcre2* that ~pkg-config~ can see and *zlib* (~brew install
  pcre2~ or ~apt install libpcre2-dev zlib1g-dev~), *python3* and *awk*, and
  oha, the load test's client, whose release binary ~make oha~ downloads and
  checks (macOS and Linux, amd64 and arm64)

Dependencies are pinned git submodules under ~vendor/~ (chez-libuv,
chez-httparse, uriparse, chez-srfi and vtest2 for the tests; byte-machine
arrives under chez-httparse):

#+begin_src sh
git clone --recursive https://github.com/Kiyomi-Computation-Systems/chez-http-server.git
cd chez-http-server
make build   # builds the chez-libuv shim and assembles the one library path
make test    # runs every tests/test-*.sps
#+end_src

~make test~ builds vtest2 and downloads oha itself the first time.
~make help~ lists every target; ~make check-pins~ verifies each submodule sits
at its pinned release commit.
