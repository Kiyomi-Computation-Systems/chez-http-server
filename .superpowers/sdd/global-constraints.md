## Global Constraints

Every task brief in this project is bound by the following. They are the house rules the sibling projects (`chez-libuv`, `chez-httparse`, `uriparse`, `byte-machine`) enforce, restated in chez-http-server's spellings.

- Toolchain floors: Chez Scheme 10.4.1 (the full system, threaded build; Petite is rejected), libuv 1.48.0 or later in the 1.x series (1.44.0 until chez-libuv v0.8.0) through chez-libuv's own acquisition paths, which pass a system libuv below it over for the vendored build, CMake 3.10 or later where CMake is used, which is only chez-libuv's vendored libuv build: libuv's CMakeLists asks for 3.10, and Debian 12's 3.25.1 builds v0.8.0's libuv 1.52.1 (measured 2026-10-09). The 3.26 written here until then is chez-httparse's, uriparse's and byte-machine's own floor, set by CMake presets this build never runs. Measured here 2026-09-19 on Darwin arm64: Chez 10.4.1 `tarm64osx`, libuv 1.52.1, CMake 4.3.3.
- Dependencies are pinned checkouts by gitlink at release tags: chez-libuv at the v0.8.0 tag (ad3bb47: `uv-write*!`, `uv-tcp-keepalive!` and the reuseport bind flag, `uv-tcp-sockname-address`, `uv_run` and its trampolines `__collect_safe`, `(libuv async)` and enforced loop-thread affinity with `&uv-wrong-thread` since v0.6.0; `uv-update-time!` for #28 since v0.7.0; bytes copied, and blocks zeroed, in bulk for #35 since v0.7.1; `uv-async-send!` fenced against `uv-close!`, `uv-close!` one step even inside an engine, and a Chez without threads refused by name since v0.7.3; one guarded seam per callback, `uv-run` without `dynamic-wind` and libuv's read alloc callback answered in the shim for #45, each stream verb and constructor one step no engine splits, and a caller's data read once, since v0.7.4; every verb's checks and its native call in one step, seven verbs that answered 0 answering nothing, and a libuv below 1.48.0 refused at load, since v0.8.0), chez-httparse at the v0.4.5 tag (0b7058e: `(httparse decisions)` and `(httparse methods)` since v0.3.0, the `parser-finish!` fixes for #33/#42 and the #34/#36 documentation since v0.4.0, the `upgrade` field documented for #47 since v0.4.1, the Transfer-Encoding note corrected for #50 in v0.4.2, what `parser-stream-offset` answers inside a callback documented for #55 and an empty close-delimited body no longer delivered at finish (#57) in v0.4.4; v0.4.5 pins byte-machine v0.7.0 at c338a57, whose keyword walk reads its prefix in place for byte-machine #139 since v0.6.1, and whose parse errors name the span they abandoned and where its withheld bytes begin for byte-machine #145), uriparse at the v0.6.2 tag (5ecd88f: `uri-collector-reset!` for #11 and the audited recognizer-equivalence claim for `uri-parse-validate` since v0.3.0, `uri-parse-result-validate` for #18 since v0.4.0, `validate-component` over a range for #21 since v0.5.0, `validate-authority` and `authority-host-span` over a range for #24 since v0.6.0; v0.6.1 moved its byte-machine to v0.6.1, and v0.6.2 moves it to v0.7.0 at c338a57, the commit chez-httparse vendors too). A pin moves alone, on its own commit, with a fingerprint or byte-identity check. byte-machine is one pin with two carriers: chez-httparse and uriparse each vendor it, and `make check-pins` holds uriparse's to the one on the library path, so it moves through both on one commit. No other dependencies without a decision record.
- Pure libraries under `src/http-server/` import `(rnrs)`, `(rnrs mutable-strings)`, `(byte-machine runtime)`, `(generated httparse-message)`, `(httparse modes)`, `(httparse decisions)`, `(httparse methods)`, `(uri ...)` and this project's own pure libraries, and nothing else; an import-audit lane asserts it. (The two `(httparse ...)` tables joined this list with design §3.1; M2.2's connection core is the first pure library to import them. `(rnrs mutable-strings)` joined it with M4.5, 2026-09-27: `(rnrs)` leaves out `string-set!`, and the handler's view fills the fresh strings it returns with it, as the serializer fills fresh bytevectors. Measured on an 11-byte path, Darwin arm64: 64 B that way, 96 B through a UTF-16 bytevector, 2,048 B through a Latin-1 transcoder.) `(libuv ...)` and `(chezscheme)` appear only under `src/http-server/private/`, the test harness and the Makefile.
- Every `.sls` and `.sps` carries a `#!r6rs` line. Libraries contain their own code; no shared include bodies. Exported procedures carry a Typed-Racket-style signature comment.
- Exit-status vocabulary for Scheme lanes: 0 pass, 1 assertion failure(s), 2 harness/configuration/registration error (includes empty selection), 3 provenance failure. Empty selection is failure at every layer.
- Every `tests/test-*.sps` ends with its own `(exit ...)`; SRFI-64 sets no process status. Assertions compare against a value only success can produce, never `#f`, never bare truthiness.
- A test is finished when it has been watched to fail: the named mutation breaks the asserted property and nothing else, is recorded in the milestone's mutation log, and is reverted. A survivor is a missing test, a scope statement, or the finding itself, and which one is measured.
- Numbers in a test come from an oracle (a fixture, a measured libuv fact, an RFC vector), never from running the code under test. A refusal to render an unreproducible value is an outcome, not a crash.
- Socket tests bind `127.0.0.1:0`, run clients on the same loop, and cap by iteration count, never wall-clock. Timeout tests drive `(tick now)` with a fake clock.
- Every count that enters a record is re-measured on the tree at the time of writing, dated and platform-stamped; do not carry numbers forward by arithmetic.
- Conventional Commits. Run `make test` before every commit; fix failures first. CI is Linux only.
- Prefer a check to a comment: a load-bearing invariant becomes a make target, a test, or an assertion (`handle-close!` is the one `uv-close!` caller, for every kind of handle; handler-facing libraries export no `uv-*` name; the pure libraries import no libuv; nothing a parser feed runs can reach the scheduler: the pure libraries import no private library, and the adapter neither the scheduler nor the shell or serve, M7.1).
